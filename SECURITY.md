# Security policy

## Reporting a vulnerability

Report through GitHub private vulnerability reporting on this repository, or
through the owner's published GitHub profile contact method. Do not open a
public issue for a vulnerability, and do not include credentials, Azure
subscription identifiers, or private environment data in a report.

Include the affected workflow or file, the impact observed, and the smallest
reproduction that shows it. Redact anything not needed to reproduce.

## Scope

This repository is an isolated manual pilot example with no production state or
scheduled live jobs. Reports that could compromise reusable workflow inputs or
token permissions are in scope.

## What happens next

The maintainer acknowledges a report on a best-effort basis and coordinates the
fix and disclosure timing with you. There is no bounty and no guaranteed
response time.
